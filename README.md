# Форма регистрации и авторизации + права доступа (Flask)

## Запуск

```bash
pip install flask
python app.py
```

Открыть: http://127.0.0.1:5000

## Учётные записи (создаются при первом запуске)

| Роль  | Логин | Пароль     |
|-------|-------|------------|
| user  | user  | User123!   |
| admin | admin | Admin123!  |

Новые пользователи, зарегистрированные через форму, всегда получают роль `user`.

## Что реализовано

- Регистрация с проверкой логина и пароля
- Вход / выход, сессии
- Пароли хранятся в виде хеша (werkzeug, scrypt/pbkdf2), не в открытом виде
- Две роли: `user` и `admin`
- Страница `/admin` доступна только администратору (для остальных — 403)
- CSRF-токен во всех POST-формах
- База данных SQLite (`users.db`)
- **Настройка прав доступа для учётной записи user** (см. ниже)

## Права доступа

Администратору доступно всё. Обычному пользователю доступны только те разделы, на которые
администратор выдал право.

| Код права      | Раздел     | По умолчанию у нового пользователя |
|----------------|------------|-------------------------------------|
| `view_reports` | `/reports` | да                                  |
| `view_files`   | `/files`   | нет                                 |

Как настроить: войти как `admin`, открыть «Админ-панель», в строке пользователя нажать
«Настроить», отметить нужные права и сохранить. Изменения действуют сразу. Раздел без права
отвечает **403**, ссылки на недоступные разделы в меню не показываются.

### Как это устроено

- Таблицы `permissions` (справочник прав) и `user_permissions` (какие права у какого
  пользователя). Они создаются автоматически, в том числе в уже существующей `users.db`.
- Список прав задаётся в `PERMISSIONS` в `app.py`, права по умолчанию — в `DEFAULT_PERMISSIONS`.
- Декоратор `@permission_required("код_права")` защищает маршрут. Он сначала проверяет вход,
  затем наличие права, иначе отдаёт 403.
- В шаблонах доступна функция `can("код_права")`.
- Чтобы добавить новый раздел: добавить запись в `PERMISSIONS`, написать маршрут с
  `@permission_required(...)` и шаблон.
- Администратор не может менять права другому администратору (у админа всегда все права),
  а сам пользователь не может выдать права себе: `/admin/users/<id>` закрыт `@admin_required`.
- Из формы принимаются только коды из справочника, остальные значения отбрасываются.
